# Agentic-workflow adoption taxonomy

A researched crosswalk from team-adoption failure themes to Ready Agent 1 coverage. Every row names
bounded recurrent failures, the criteria/proxies covering them (present today or added in 0.11.0),
the 0.11.0 response, and the residual/unscored boundary. This is durable research-to-product evidence
for future coverage work — not a claim that any criterion proves organizational adoption.

Primary sources motivating the domains: NIST AI RMF 1.0 (transparency/provenance), SLSA v1.0 and
in-toto Statement v1 (artifact provenance fields), the SPACE and DevEx frameworks (multidimensional,
team-level productivity), the DORA AI Capabilities Model (repository checks as partial leading
indicators), OWASP Prompt Injection and Excessive Agency (control outside model behavior), METR
experienced-developer RCT and its 2026 design update (perceived vs measured outcomes), OpenAI Harness
Engineering (legibility, isolated reproducibility, mechanical invariants, recovery), and Anthropic
Context Engineering (finite context, progressive disclosure).

Status vocabulary: `existing` (shipped before 0.11.0), `added` (shipped in 0.11.0), `proxy`
(partial leading indicator with a documented boundary), `deferred` (explicitly out of this release).

| # | Domain | Recurrent failures | Current criterion / proxy IDs | 0.11.0 response | Residual / unscored boundary |
|---|---|---|---|---|---|
| 1 | Task definition & decomposition | Work enters the agent without an owner, a definition of done, or a verification path | `docs.agents_md*` (existing/proxy), `taskdisc.pr_evidence_contract` (added), `build.check_command` (deepened) | PR evidence contract requires intent/verification/risk/recovery sections; single verify entrypoint designates the inner loop | Template content does not prove authors complete or reviewers enforce it; decomposition quality itself is unscored |
| 2 | Context & durable knowledge | Agents re-derive or hallucinate project context; docs drift | `docs.agent_context_map` (added), `docs.machine_context` (deepened), `docs.architecture_doc`/`docs.runbooks` (existing) | Progressive-disclosure map from root AGENTS.md to present, filled local docs; conservative MCP/llms shape checks | Referenced docs' correctness/freshness beyond 180-day staleness is unscored; runtime retrieval unscored |
| 3 | Architecture & maintainability | Agents cannot see system shape or ownership; changes collide | `docs.architecture_doc`, `docs.domain_docs`, `security.agent_config_ownership` (added), `security.codeowners` (existing) | Every recognized agent-control file must resolve to a definitive CODEOWNERS owner under the documented subset | Ownership syntax does not prove identity/access/review; architecture fitness unscored |
| 4 | Environment & reproducibility | Commands fail locally; setup is tribal | `devenv.devcontainer`, `devenv.env_template`, `devenv.local_services` (existing) | (unchanged) | Runtime environment parity and container behavior unscored |
| 5 | Inner-loop verification | Agents claim success without running checks | `build.check_command` (deepened), `devenv.agent_hooks` (deepened), `testing.tests_pass` (T3, existing) | Strict verify-command grammar (make/just/task, npm/pnpm/yarn scripts, python -m pytest/unittest/mypy/ruff, scripts/ paths); hook parsing rejects shell-embedded commands | A documented command is not execution; hook wiring is shape-only |
| 6 | Behavioral validation & mergeability | Autonomous merges without evidence; PRs lack proof | `taskdisc.pr_evidence_contract` (added), `build.ci_runs_tests` (existing/T2), `build.ci_duration_budget` (existing) | PR templates must carry verification and blast-radius/recovery sections | No proof authors complete or reviewers enforce; CI run parsing is projection-only |
| 7 | Review capacity & ownership | Nobody owns the code; reviews are lottery | `security.codeowners`, `security.agent_config_ownership` (added), `taskdisc.review_latency` (existing/T2) | Ownership subset covers agent-control files incl. the CODEOWNERS file itself | Real review identity/behavior and org process unscored |
| 8 | Agent permissions & control plane | Agents get over-broad bash/allow rules; secrets readable | `security.agent_permissions` (deepened), `.claude/settings.json` + `.agents/**/permissions*` (existing) | Full mode evaluation: bypass fails, broad/dangerous allows fail, mandatory secret-class denies, protected-control mutation guards, acceptEdits consequence guards | Static policy shape is not runtime enforcement, identity, or sandbox proof |
| 9 | Prompt injection & untrusted inputs | Agents act on hostile issue/PR/web content | `security.agent_permissions` (proxy), `security.supply_chain_provenance` (proxy) | Engine treats all repository/report/policy content as data; skills copy canonical payloads only | Effective untrusted-context isolation and prompt-injection resistance are unscored and cannot be proven by text evals |
| 10 | Supply chain & tools | Builds depend on unverified artifacts | `security.supply_chain_provenance` (added), `build.release_automation` (migrated), `security.dependency_update_automation` (existing) | Scope-valid attestation/SLSA wiring when publication intent is present; conservative three-state applicability | Wiring shape does not prove successful runs, distribution, or released-artifact coverage; no signature verification |
| 11 | Sandbox, egress, identity & audit | Escaped commands, leaked credentials, no audit | T3 opt-in (existing), `assessment_boundary` (added), `assessment_provenance` (added) | Explicit boundary discloses unscored runtime isolation/egress/identity/audit; provenance is unsigned metadata | OS/container isolation, least-privilege credentials, human approval, kill switches, recovery drills: defer |
| 12 | Parallel work & recovery | Concurrent agents stomp each other; merges break | `taskdisc.concurrent_agent_protocol` (added) | Four distinct documented statements: isolation/ownership, coordination, change preservation, integration verification | Documented protocol is not proof of isolation/collision avoidance/merge correctness/verification execution |
| 13 | Operations & production safety | Deploys without rollback paths; incidents untrained | `taskdisc.pr_evidence_contract` (risk/recovery, proxy), `observability.*` (existing) | Recovery section required in PR templates | Production behavior, incident response, and recovery drills are unscored |
| 14 | Organization & people | Adoption is a mandate, not a practice | — | Boundary documents org policy/adoption as unscored; graduation requires human ADR review | Organization policy enforcement, ownership behavior, adoption, and outcome improvement are deferred |
| 15 | Measurement & ROI | Velocity theater; outcomes unmeasured | `history` deltas (existing), `docs.doc_freshness` (existing) | Readiness history measures repository evidence changes only — never DORA/DevEx/ROI outcomes | Customer-owned outcome measurement joining throughput, stability, and DevEx is deferred |
| 16 | Product experience | Tooling is noisy, unactionable, or unverifiable | renderers (deepened), `fix_contract`/`answer_contract` (added), `score.next_gate_actions` (added) | Markdown default with evidence coverage, complete next-gate blockers, decision traces, boundary/provenance; verified remediation and typed interview contracts | Agent UX beyond the shipped skills is a product iteration surface, not a readiness signal |
